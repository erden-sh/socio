---
title: 'Features and early access'
description: 'Decide which optional and early-access features this workspace has, for everyone or for some roles and people.'
---

Two pages under **Settings → Workspace** decide which switchable features this workspace has:

- **Optional features**: released features that stay switchable. They are usually on; turn one off, or keep it for some roles and people only.
- **Early access**: experimental features, ready to try before they are released. They carry an **Early access** badge and may still change or go away. They are off until you turn them on.

People can't turn a feature on or off for themselves: only this page decides who has it, together with this server's configuration.

Each feature shows whether it is on for everyone and for you, and where that comes from: its default, this server's configuration, or this workspace's rule. When this server's configuration says something about the feature, a line starting **Set by this server's configuration** says what, read-only. Its key, owning area, removal date and socio tools are under **Details**. When a page lists many features, a search box filters them.

## Set the workspace's rule

For each feature, choose who has it in this workspace:

- **No workspace rule:** follow the default, or this server's configuration.
- **On for everyone** or **Off for everyone.**
- **On for some roles and people:** tick roles and people. It is off for everyone else.

Save applies the rule to each person's next request and their socios' next turn. When a feature is off for someone, its socio tools are not in their turns, so a socio can't use or offer them.

## What you can't change

This server's configuration decides some features: you can't set a rule for one it has fixed, or one this workspace's plan leaves out. The feature says why, in place of the rule.

## In development

Unfinished features are only for the team that builds Socio. A deployment marked internal lists them under **Settings → In development**, where admins switch them like any other. Other deployments never list them, and never have them on.

## Changes are recorded

Every change to the workspace's rule is recorded with who made it and when; changes to this server's configuration are recorded too, without a name. **Recent changes** at the end of each page shows the latest for its features.

People can read what early access means for them in [Early access](/docs/early-access).
