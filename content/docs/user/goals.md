---
title: 'Goals'
description: 'Give a socio an outcome to work toward over time.'
---

A goal is an ongoing outcome for a socio to pursue for you. “Keep our onboarding checklist current” is a goal; “send the same summary every Monday” is better suited to a fixed [schedule](/docs/schedules). A goal has its own work conversation, cadence, status, progress and comments.

## Describe an outcome

Tell the socio what success means, which sources it should use, how often it should work and what limits apply. Include an end condition when possible: “Find three suitable venues by Friday, compare capacity and price, and ask before contacting anyone.” The socio proposes the goal, and you approve it before it starts unless you have deliberately configured a bypass policy.

Read the [approval](/docs/approvals) carefully. A goal is permission to pursue a stated outcome with existing tools, not blanket permission for every external action. Separate actions can still need approval.

## Follow progress

Open **Schedules & jobs** to see your Goals. A goal shows its status, cadence and latest progress note. Where a conversation link is present, open it for the underlying work. Expand comments to add context or a changed requirement without creating another goal. The socio reads those comments as it continues.

If you ask for something similar to an existing active, paused or waiting goal, Socio can identify possible duplicates. Add to the existing goal unless you intend a separate outcome. Confirm that distinction before asking for another one.

## Pause, cancel or finish

Use the associated schedule to pause or cancel a goal's recurring work. Pausing is useful while requirements change; cancellation is appropriate when the outcome is no longer wanted. The socio marks the goal done when it is met and should record what it achieved. Read that evidence rather than assuming that a “done” label independently verifies the result.

Ongoing work requires a running server, an available model and the necessary capabilities. Check its schedule and approvals if progress stops. Jobs that run code until complete have a different progress mechanism; see [schedules and jobs](/docs/schedules).
